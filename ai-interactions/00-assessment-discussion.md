我看完了这个 PDF。这是一份 **Ocean AI Labs Beijing 的技术面试实战考核说明（Technical Interview Assessment）**。

它不是传统的算法面试，而是一个 **3 小时的 Full-Stack Take-home Assessment**。比较特别的是，**面试官明确鼓励你使用 AI 编程工具，甚至预期你用 AI 生成整个代码库**。

他们真正想考察的是：你能否利用 AI，在有限时间内设计、开发、测试并交付一个完整的小型产品。

## 一、你需要做什么？

项目叫做 **Certificate Admin Console（证书管理后台）**。

背景是一家企业培训 SaaS 平台，不同企业（Tenant）可以管理自己的课程、学员和结业证书。

你需要从零开发一个管理后台。

### 四个必须实现的功能

| 功能 | 具体要求 |
|--------|--------|
| 1\. 证书列表 | 支持姓名或证书编号搜索、分页、排序，以及 Loading、Empty、Error 三种状态 |
| 2\. 批量颁发证书 | 选择课程，一键为符合条件的学员颁发证书；防止重复颁发，显示执行进度和每个学员的结果 |
| 3\. 证书详情 | 展示证书编号、课程、学员、颁发时间、有效或撤销状态，并支持确认后撤销 |
| 4\. CSV 导出 | 导出当前 Tenant 的证书，遵守搜索筛选条件，大数据量下也要正确运行 |

此外，还有几个非常关键的后端要求：

- **Multi-tenancy**：不同租户之间必须数据隔离。
- **Idempotency**：批量颁发接口即使重复调用，也不能重复创建证书。
- **Audit Log**：每次证书颁发都必须有审计记录。
- **Timezone**：日期必须按照 Tenant 所在时区显示，而不是简单使用 UTC。

## 二、允许使用什么技术？

|  | 允许的技术 |
|--------|--------|
| Frontend | React / Vue 3 |
| Backend | Node.js / Python / Go |
| Database | SQLite / MySQL / In-memory |
| AI Tools | Cursor / Claude Code / ChatGPT / Copilot 等 |

结合你之前的技术栈，我建议使用：

**React + TypeScript + Vite + FastAPI + SQLite**

这套技术你已经很熟悉，可以把更多时间用在业务逻辑和边界条件，而不是搭建环境。

## 三、面试如何进行？

总时长：180 分钟，一次完成

有几个规则需要特别注意：

- **全程录屏，摄像头一直打开**，使用他们安排的 Lark 会议。
- 编辑器、终端、AI 工具都需要出现在录屏中。
- 开发过程中要持续提交 Git Commit。
- 需要保留 AGENTS.md 等 AI 指令文件。
- 最后 25 分钟的 Reflection 和 Design Questions 要求你**独立作答，不使用 AI**。

## 四、他们真正考察什么？

PDF 第 4 页明确列出了评估标准。除了最终能运行的产品，还特别关注：

1. **AI 使用能力**：你如何给 AI 提供上下文、验证 AI 生成的代码，以及发现和修复错误。
2. **System Design**：数据模型、API 设计、前端状态管理、系统扩展性。
3. **工程细节**：特别是幂等性、租户隔离、时区、审计日志。
4. **交付能力**：能否启动、演示、测试，并提供清晰的 README。
5. **优先级判断**：文档明确说不要求实现所有东西，合理取舍本身也是考核的一部分。

## 五、最终需要提交什么？

- Git Repository 链接及完整 Commit History
- 全程录屏的云盘链接
- 初始开发计划及 AI Instruction Files
- Demo Data / Seed Script
- 书面 Reflection 和 Design Questions 的答案

他们表示会在两个工作日内审核。如果通过，下一轮是 **60 分钟的 Final Interview**，其中包含你亲自演示项目，以及解释 AI 生成的代码和设计决策。

## 我的判断

**这份考核更偏向 Senior Full-Stack / AI-assisted Engineering，而不是 LeetCode Coding Interview。**

对于你这种有 React、FastAPI、SaaS 和 AI 开发经历的工程师，技术选型和基础 CRUD 应该不是主要难点。

- 批量颁发证书的幂等性和并发正确性。

如果你准备参加这场考核，我建议重点准备的是：**如何在 120 分钟的实际编码时间里，把这四个功能实现到可演示、可验证的程度。**

# 技术面试考核

**候选人说明文件（Candidate Briefing Pack）**

**项目：证书管理控制台（Certificate Admin Console）**

**考核时长：3 小时 · 一次连续完成 · 从零开始使用 AI 构建**

**请在开始之前完整阅读本文件。**

## 1\. 欢迎（Welcome）

感谢你抽出时间参加本次考核。

这项考核将取代传统的现场编程面试（Live Coding）。

本次考核不会提供任何初始代码、现有代码仓库，也不会提供预置数据。

你需要从一个完全空白的开发环境开始，像处理实际工作任务一样，构建一个规模虽小但功能完整的产品。

在这个过程中，你需要：

- 制定开发计划。
- 指导和使用 AI 工具。
- 验证 AI 工具生成的内容。
- 在时间有限的情况下，判断哪些事情最重要。

如果你能够合理管理项目范围，那么三个小时足以完成这项任务，包括测试和必要的细节打磨。

## 2\. 需要构建的产品（The Product to Build）

你需要为一个\*\*多租户企业培训平台（Multi-tenant Corporate Training Platform）\*\*开发一套内部管理控制台。

企业客户（称为 Tenant，即租户）使用该平台为自己的学员开展培训课程。

当一门课程结束后，该租户的管理员会通过这个控制台审核并颁发课程结业证书。

### 业务背景（Business Context）

- 该平台服务于多个租户。一个租户绝对不能查看另一个租户的数据。
- 每个租户都有自己的时区，例如 `Australia/Sydney`（澳大利亚悉尼）和 `Australia/Perth`（澳大利亚珀斯）。租户管理员希望系统按照自己所属的时区显示日期。
- 租户（Tenants）、课程（Courses）、学员（Learners）、课程注册记录（Enrollments）以及证书（Certificates），是该系统的核心业务实体。你可以自行决定如何定义这些实体，并自行创建演示数据。
- 批量颁发证书的操作可能通过不可靠的网络触发，因此可能发生重试。即使同一个操作被执行多次，系统也必须正确处理。
- 每一次证书颁发都必须写入审计日志（Audit Trail），记录由谁颁发、何时颁发，以及对应的课程和学员。

## 3\. 功能要求（Requirements）

### 核心功能（Core）

以下四项功能全部为必需功能。

### 1\. 证书列表页面（Certificate List Page）

为当前选定的租户提供一个证书列表页面。

页面必须支持：

- 根据学员姓名搜索。
- 根据证书序列号（Certificate Serial Number）搜索。
- 分页（Pagination）。
- 排序（Sorting）。

此外，页面还必须明确处理以下三种状态：

- **加载状态（Loading）**：正在获取数据。
- **空结果状态（Empty Result）**：没有符合条件的数据。
- **错误状态（Error）**：获取数据时发生错误。

### 2\. 批量颁发证书（Bulk Issue）

管理员可以选择一门课程，通过一次操作，为该课程中所有符合资格的学员颁发证书。

具体要求如下：

- 通过选择课程发起批量颁发操作。
- 一次性为所有符合资格的学员颁发证书。
- 颁发按钮必须防止重复提交。
- 界面必须展示操作进度。
- 由于网络原因，同一个操作可能被重复请求，因此后端必须正确处理重复调用。
- 操作完成后，必须展示每个学员对应的处理结果：
  
  - `issued`：已颁发。
  - `skipped`：已跳过。
  - `failed`：颁发失败。
- 每一次成功颁发证书，都必须写入对应的审计日志。

### 3\. 证书详情（Certificate Detail）

证书详情页面必须展示以下信息：

- 证书序列号（Serial Number）。
- 所属课程（Course）。
- 对应学员（Learner）。
- 颁发日期（Issue Date），必须按照当前租户所在的时区显示。
- 证书状态（Status）：
  
  - `valid`：有效。
  - `revoked`：已撤销。

此外，还必须提供撤销证书的操作（Revoke Action），并在执行撤销之前显示确认提示。

### 4\. CSV 导出（CSV Export）

系统必须支持为当前选定的租户导出证书数据。

导出操作必须遵循当前页面的搜索条件或筛选条件。

CSV 文件需要包含以下字段：

- 学员姓名（Learner Name）。
- 课程名称（Course Title）。
- 证书序列号（Serial Number）。
- 颁发日期（Issue Date）。

随着租户数据量不断增长，导出功能仍必须保证结果正确。

你可以从以下语言中任选一种：

- Node.js

- SQLite
- MySQL
- 内存数据存储（In-memory Store）

### 前端（Frontend）

可以使用：

- Vue 3
- React

可以使用 Vite，也可以不使用。

### 启动要求

应用程序必须提供文档化的启动步骤，使其能够通过简单的命令启动。

例如：

```bash
go run .
npm run dev
```

或者：


## 5\. 考核规则（Rules）

### 系统设计问题（Design Questions）

以下每个问题，用几句话回答即可。

**不要求编写实际代码。**

**问题 1：证书颁发、审计日志和通知的并发一致性**

颁发证书时，系统还必须：

- 写入一条审计日志。
- 发送一条通知。

API 接口和后台任务（Background Job）都可能发生重试，并且可能并发运行。

你将如何保证同一个学员不会被重复通知？

**问题 2：租户时区与夏令时**

证书必须按照租户本地的日历日期进行排序和导出。

但是，系统中的时间戳统一使用 UTC 存储。

一位同事提出了以下方案：

为每个租户保存一个固定的 UTC 时差，例如：

- 悉尼：UTC+10
- 珀斯：UTC+8

然后在系统所有地方使用这个固定时差进行时间转换。

然而，悉尼实行夏令时（Daylight Saving Time），而珀斯不实行夏令时。

这种设计方案会出现什么问题？

你会如何改进并实现它？

**问题 3：大数据量 CSV 导出超时**

某个租户的数据量增长到了 100,000 张证书。

此时，CSV 导出操作发生了超时。

请逐步说明你会如何修复这一问题。
